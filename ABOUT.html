About

The story behind Klunk - Log Viewer, and the person who makes it.

What Klunk is

Klunk - Log Viewer is a desktop application for reading logs from — local files, databases, Kubernetes pods, SFTP servers, and HTTP endpoints — in one place. It merges multiple sources into a single timeline, filters them with a SQL-like query language, and stays responsive at millions of rows. Everything runs on your own machine.

Why I built it

Klunk started as a personal tool to help me read and analyze logs more efficiently. It has grown from a weekend utility into the log viewer that I now reach for when I need to dig through dev logs, and it is shared in the hope that it is useful to other people who spend their time in logs.

Who makes it

Klunk was designed and built by Michael Dow, operating as KookaKlunka Studios, LLC. It is an independent, self-funded project — no investors, no outside stakeholders, just one developer and hopefully further progressed by any users who find it useful and/or send in bug reports and ideas.

What it stands for

  • Local-first. Your log data is parsed, indexed, and stored only on your own machine. Nothing is uploaded. See the Privacy Policy.
  • No telemetry. No analytics, no crash reporting, no feature-usage metrics. Not now, not later.
  • Free to use. No license key, no seat count, no subscription — see the Terms of Use.
  • A real desktop app. Native windows, keyboard shortcuts, dockable tabs, and session persistence — not a browser tab pretending to be an application.
  • Built to last. A focused tool that does one job well and is maintained over the long term.

How it's built

Klunk is a Java 25 application built on JavaFX 26, with an embedded SQLite database powering its virtual-scrolling and filtering engine. It builds on a number of open-source libraries, each under its own license — they are listed under Third-party software below. The installer bundles its own Java runtime, so there is nothing else to install.

Status and roadmap

Klunk is currently in beta and believed to be very stable, but please report any bugs you find. The roadmap is to continue improving the core log-viewing experience, but of course, depends on whether users find it useful enough to keep it going. Feature requests are welcome, but there are no guarantees that they will be implemented. Releases and release notes will be published on the releases page.
